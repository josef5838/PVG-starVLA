# adjust_bottle camera-stream training and evaluation

The comparison is direct conditioning on 408 camera/register tokens versus a learned fuser producing 32 tokens. Each policy uses three independent eight-image Omega calls, frozen official Omega512 weights, camera/time/type embeddings, state and task conditioning, and the same diffusion action decoder. There is no temporal RoPE. Both completed 10,000 updates / 80,000 observations with seed 42.

## Registered evaluation

Primary closed-loop checkpoints are selected using the existing held-out validation MSE: direct update 9,750 and fused update 9,000. Both final update-10,000 checkpoints are also scored offline. Do not select checkpoints based on rollout success.

Recorded-trajectory evaluation covers all 45 training trajectories at eight equally spaced anchors each (360 examples), and all five held-out trajectories at 16 anchors each (80 examples). Evaluate identical anchors and batches for both policies and checkpoint types. Use the production dataset packing, normalization, causal histories, frozen backbone and DDIM20. Noise seed is 4000 + batch index. Measure normalized action MSE over all 16 targets, valid future targets excluding episode-end padding, the executed first eight targets, and the first target; also joint RMSE, active-arm RMSE, gripper accuracy and a hold-current-state reference. This is teacher-forced action prediction, not task completion.

Closed-loop evaluation uses five seen training episodes [0, 10, 22, 35, 48], all five held-out episodes [5, 20, 25, 39, 49], and five independent evaluation seed starts [100000, 200000, 300000, 400000, 500000]. Reject unstable initial setups, then accept the first stable seed in each sequence, without expert-feasibility rejection or policy-outcome selection. Accepted seeds are [100001, 200001, 300000, 400000, 500000]; the first two starts fail the simulator's stability check. Fresh cases comprise three right-arm and two left-arm scenes. They are a paired unseen-scene diagnostic, not a full official benchmark submission. The held-out split was used for checkpoint selection and is not an independent test set. Fresh seeds are independent of that selection.

Resolve converted episode IDs to original source IDs by matching every observation state to source command t and every action to source command t+1. Require a unique match for each of all 50 trajectories. For recorded initial scenes, additionally verify initial simulator state, all three initial RGB images (MAE <= 6 in source RGB units), and object model. Failed scene verification invalidates the rollout; it is not counted as a policy failure. Fresh seeds use the same demo_clean task configuration but have no recorded initial-image comparator. All 50 source demonstrations use the right arm; report the arm for fresh cases explicitly.

The client stores the latest eight observations of each camera at every policy control step, including steps that reuse an action chunk; histories are chronological and the first image is duplicated on the left at episode start. Resize simulator images to the actual dataset's 640x480 before unchanged official Omega preprocessing (448x592). Action horizon is 16, execute horizon eight, DDIM20, diffusion seed 4000 + replan index, absolute joint commands with the production state/action ordering and normalization. The simulator's normal TOPP control path determines elapsed physical time, so eight rollout observations are not guaranteed to span the nominal training window of 7/15 seconds.

Use the simulator's unmodified adjust_bottle success criterion (bottle functional point above 0.9m and on the target side) as the primary endpoint. Also report closed-gripper contact with two gripper bodies, any actor-origin lift of at least 4cm, maximum lift, action/state traces and head-camera videos. These secondary signals need not be prerequisites for the task's success criterion. Record all cases up to success or the official 400-step limit. Decode completed videos fully with ffmpeg.

Replay ten matched recorded expert trajectories through the same ModelClient action scheduler and simulator controller as a control. This oracle bypasses policy inference and supplies recorded raw actions in policy order; it does not test the learned policy or websocket inference. Also replay the same ten experts after the exact training action transform and its inverse. The second control checks whether binary gripper targets affect execution; joints round-trip to within 1.8e-7 rad, while grippers can differ by up to 0.4724. Distinguish failed expert replay from policy failure when interpreting the benchmark. The normalization control was added after failure inspection, as a diagnostic, not to select policy checkpoints.

Archive scripts, checkpoint SHA256 hashes, splits, trajectory mappings, seeds and results. Summarize training loss and held-out action MSE separately from closed-loop success. A single training seed and five scenes per evaluation subset cannot establish a general advantage of geometric conditioning; comparison to RGB/state baselines and larger repeated-seed evaluation remains future work.
