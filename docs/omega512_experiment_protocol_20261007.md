**Omega-512 experiment protocol — registered 2026-10-07 UTC**

This protocol records the next policy experiments before running them. These policy trainings are planned, not launched by this document. The reconstruction study below is authorized for immediate execution. The hypotheses, inclusion rules, settings, and outcome definitions should remain visible if later amendments are needed.

1. **Reference fitting experiment.** Keep the frozen official Omega-512 backbone and current dense action architecture. Use eight varied training trajectories, retaining the original normalization statistics and temporal contract (observation t predicts command t+1). Fix the selected episodes in a manifest before training. Include varied object locations and similar starting robot configurations; use only the supported right-arm domain until left-arm demonstrations and normalization are available. Keep the image preprocessing, action representation, diffusion objective, optimizer settings, chunk size, and execution horizon fixed. Start fresh, with a 20,000-update budget, the original effective batch size of eight, and complete resumable saves every 5,000 updates. Probe 128 preselected phase-stratified training observations every 500 updates with fixed noise; enumerate the complete eight-trajectory set at saved checkpoints. Track exposure per frame and training-trajectory action error. Assess convergence from the complete curve rather than the last loss, and report any continuation as an amendment. Evaluate all eight matched training scenes at checkpoints 10,000 and 20,000 using execution horizon eight and sampling seeds 4000/4001/4002. Report full task success and grasp/lift outcomes separately, plus gripper timing and end-effector errors near contact.

2. **Frozen visual feature probe.** Train small visual-only predictors for object location and object-to-gripper displacement, using simulator supervision. Split whole trajectories rather than frames, and fix the split in a manifest before fitting. The predictors must not consume state, action, episode ID, or time index. Include constant/mean predictors and an image-shuffle control. Report object and gripper localization separately so that reading arm geometry is not mistaken for object grounding. Geometry coordinates require a documented camera-to-robot frame and scale. Failure of one probe is evidence about accessibility under that probe, not proof that the backbone contains no useful information.

3. **Shared observation encoder ablation.** Feed Omega spatial tokens, projected robot-state tokens, and the existing task token into a shallow trainable observation transformer with modality/view/spatial embeddings. Its observation memory conditions the current action DiT. Remove the separate decoder-state prefix for this variant; keep state in the observation encoder. Preserve spatial visual tokens initially. Compare with the fitted dense reference on identical episodes, exposure, normalization, action objective, rollout settings, and sampling seeds. Document parameter and compute differences. A fused representation can still carry state alone; this experiment tests where fusion happens, not guaranteed visual dependence.

4. **Guided retrieval ablation.** Compare learned queries with state/task-conditioned queries reading the same dense visual memory across all three cameras. Preserve local tokens alongside retrieved context. Match query count/module size and independently toggle the direct decoder-state route. Keep geometry positional embedding changes and auxiliary objectives as separate follow-ups to avoid changing several hypotheses at once.

5. **Dependence and recovery tests.** Move the object while keeping initial robot configuration fixed and obtain successful expert actions for those scenes. Compare policy responses with matched noise. Separately test swapped images, camera removal, and object-region occlusion as input dependence probes. Distinguish these corrupted inputs from physically consistent scene interventions. Log commanded targets and measured qpos; switching the state definition requires matching training and evaluation changes. Attention plots and average noise loss do not establish a causal explanation.

The decision sequence is: demonstrate repeatable fitting on the small varied set; check visual information accessibility; compare fusion; add a visual object/gripper objective if supported; consider selected Omega-layer adaptation only after these tests. Full surface reconstruction losses remain deferred.

**Registered reconstruction comparison**

- Question: does the poor Surflo wrist geometry recur on additional RoboTwin scenes, and is distortion already visible in the guided Gaussian representation or mainly introduced by mesh extraction?
- Methods: released Surflo EMA with full default rendering guidance and DA3 depth/normal experts; the VGGT geometry produced by that encoder; installed official VGGT-Omega-256-Text; verified official VGGT-Omega-512. No policy-finetuned compressor weights are substituted.
- Sampling: tasks `rotate_qrcode`, `adjust_bottle`, and `stack_blocks_three`; source episodes 7 and 23 in each task. For each episode, use frame 0 and a deterministic interaction frame: first active gripper transition below 0.5 after having been above 0.8; if unavailable, the frame of largest gripper change, or midpoint when no change exists. The selected frame rule, values, source paths, and image hashes are saved before model execution. Include every selected case, including failures; do not replace unfavorable examples.
- Inputs: synchronized head/left-wrist/right-wrist RGB decoded from source HDF5. Models receive the exact same native PNGs. Use each model's official aspect-preserving preprocessing and record resulting resolution. This is a released-pipeline comparison, not a resolution-matched benchmark.
- Surflo: seed 42; 100,000 queries; cull radius 10; plain 100-step point reconstruction; full default guided preset (50+100 flow steps, 32 inner steps, 500 polish iterations, densification, camera refinement, DA3 expert). Mesh extraction uses the default Gaussian wrapping procedure and refined cameras; coloring uses the released method. Save plain points, guided points, full guided parameters, Gaussian RGB/depth/normal renders, colored mesh, and shaded mesh.
- Depth models: save predicted camera/depth/confidence tensors and PLY meshes. Primary figures use finite positive depth without confidence filtering, with the same per-view depth-grid connectivity and 5% local-depth edge cutoff. Keep confidence-filtered figures as labeled secondary outputs. Do not silently fill holes or stitch views.
- Diagnostics: per-view Gaussian and mesh image error, mesh coverage, Gaussian alpha coverage, Gaussian-versus-mesh agreement, and relative camera rotation/center-direction errors against recorded calibration. Camera translations have arbitrary scale; any baseline-scale fit must be explicit. These are input-view and camera-consistency measurements. Source HDF5 lacks depth ground truth, so do not claim metric surface accuracy from shaded renders or RGB agreement. Shared foreground/background and geometry may be ambiguous with only three widely separated views.
- Outputs: a four-model image per case, Surflo stage diagnostics, summary figure and report, complete per-view measurements, input/calibration metadata, PLY files, and interactive viewers. Both idle local GPUs may execute independent cases. Save configuration/code provenance and stage status; checkpoint and policy training files are not changed.
- Interpretation: count failures per camera and task using both continuous measurements and visible artifacts. A recurring discrepancy across this sample supports a limitation under these tested three-view conditions, not a universal architecture failure or proof that policy features are unusable. Gaussian-versus-mesh differences help locate the failure; they do not isolate the effect of 3DGS without a separately controlled alternative representation.

Experiment 1 selects converted episodes 0, 65, 76, 2, 46, 25, 1, and 35 by deterministic farthest-point coverage of original object XY, restricted to the original training split and verified right-arm trajectories. All eight have the same initial commanded robot configuration. Original normalization, dense architecture, conditioning dropout, action objective, optimizer, chunk size 16, execution horizon eight, and native-image preprocessing are retained. Fresh training uses 20,000 updates/effective batch eight, resumable saves every 5,000, fixed 128-observation phase probes every 500, and full-trajectory probes at saves. Contact and lift are explicit diagnostic outcomes, separate from full task success.

Experiment 2 fixes 40 source scene identities, split into 24 training, 8 validation, and 8 test trajectories with seed 4242. It uses 20 observations per trajectory, five per gripper-command phase, and frozen layer-23 Omega512 features pooled to an 8×8 grid per camera. A small shared token projection and spatial MLP predicts object XYZ, right EE reference XYZ, and object-minus-EE displacement. Inputs exclude state, actions, task, time, IDs, and calibrated cameras. Coordinates use simulator world metres; the fixed robot-base transform is saved for each scene. Target standardization uses only the training set. The probe budget is 300 epochs with validation-only early stopping (patience 40), AdamW at 0.001, batch 32, and weight decay 0.0001. The train-mean baseline, a matched head evaluated with shuffled trajectory images, and a head trained with shuffled trajectory images are included. Test data select neither weights nor stopping time. Probe checkpoints preserve model, optimizer, epoch, early-stopping cursor, target scaling and RNG; `--resume-probes` restores them.

A preflight exposed a stored-plan replay mismatch: 159 regenerated observations versus 83 recorded observations for the first scene, with command/EE discrepancies that prevent reliable later-frame label assignment. Therefore experiment 2 captures RGB and object/EE poses in the same callback during newly generated simulator expert trajectories on the fixed source scene seeds. Initial image/state/model identity is checked against the source recording; original later-frame recordings are not assigned regenerated labels. The phase-selection rule is fixed before fitting; selected regenerated frame IDs are recorded during collection. Expert success is reported separately, and valid paired localization data do not depend on the expert's task-success outcome. This changes the probe image distribution relative to the original recording and is a stated limitation. See the [data amendment](../results/omega512_protocol/20261007_185108/probe_data_amendment.json). Experiment 1 still trains on the original recorded data.
